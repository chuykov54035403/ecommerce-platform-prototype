Короткая проверка проекта

1. Проверка поиска товара

curl "http://localhost:8001/products/search?q=RTX"

В ответе должны быть товары из Elasticsearch.

2. Проверка обычного заказа

Создать заказ:

curl -X POST "http://localhost:8002/orders" \
  -H "content-type: application/json" \
  -d "{\"user_id\":\"aaaaaaaa-aaaa-aaaa-aaaa-aaaaaaaaaaaa\",\"items\":[{\"product_id\":\"11111111-1111-1111-1111-111111111111\",\"quantity\":1}]}"

Скопируйте order_id из ответа.

Через несколько секунд проверьте заказ:

curl "http://localhost:8002/orders/<order_id>"

Ожидаемый статус: ASSEMBLING.

Проверьте задачу сборки:

curl "http://localhost:8004/assembly/orders/<order_id>"

Ожидаемо: задача существует, статус ASSEMBLING.

Отметьте, что заказ собран:

curl -X POST "http://localhost:8004/assembly/orders/<order_id>/assembled"

Ожидаемый статус: ASSEMBLED.

Отметьте, что заказ готов к выдаче:

curl -X POST "http://localhost:8004/assembly/orders/<order_id>/ready"

Ожидаемый статус: READY_FOR_PICKUP.

Завершите заказ:

curl -X POST "http://localhost:8004/assembly/orders/<order_id>/complete"

Ожидаемый статус: COMPLETED.

Финальная проверка заказа:

curl "http://localhost:8002/orders/<order_id>"

Ожидаемый статус: COMPLETED.

Все эти действия можно проделать через Swagger http://localhost:<порт нужного сервиса>/docs

Коротко что происходит:
- assembly-service меняет статус задачи сборки;
- отправляет сообщение в Kafka topic assembly.status;
- order-service читает это сообщение и обновляет заказ в Cassandra;
- после COMPLETED inventory-service списывает зарезервированный товар.

3. Dashboard

monitoring-dashboard - это не бизнес-сервис. Это служебная страница для отладки:
туда можно вставить order_id и быстро посмотреть статус заказа, историю, сообщения
Kafka, состояние сборки и остатки на складе.

Откройте в браузере:

http://localhost:8000/?order_id=<order_id>
